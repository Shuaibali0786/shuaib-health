# Image Manifest: Feature 001

**Feature**: 001-brand-home-page | **Date**: 2026-09-30

Every image file the pages expect, so real photos can be added later. All paths are relative to `frontend/public`. Placeholders are generated by `npm run images:placeholders` and are visibly labelled "PLACEHOLDER" with their own file name.

**To replace a placeholder with a real photo** (one image at a time, in CMD from `D:\shuaib-health\frontend`):

1. Pick a photo you own or that has a licence allowing this use: no watermark, no visible brand names or logos, and no identifiable patients without written consent. Bigger than the target size is best; the tool crops and shrinks it.
2. Fit it to the exact size and shape the page expects. This writes over the placeholder file, so no component changes are needed:
   `npm run images -- fit "C:\Users\You\Downloads\doctor.jpg" hero-doctor`
   If the automatic crop cuts off the wrong part, pick the point to keep centred with `--focus x,y` (fractions of the photo, `0.5,0.3` = middle, 30% down), which is how faces are kept whole. `--position top` (or `centre`, `bottom`, `left`, `right`) is the simpler alternative.
3. Update its `alt` text in `frontend/src/data/*.ts` so it describes the real photo (remove "placeholder image"). The hero is `heroImage` in `homeContent.ts`.
4. Verify: `npm run images -- check` lists the file as `REAL` with `ok`; then look at the page at 390 and 1280 px.

`npm run images -- check` shows every image as `REAL` or `placeholder`, its size, and any problem (wrong shape, too small, over 400 KB). `npm run images:placeholders` never overwrites an existing file unless you add `--force`, so real photos are safe.

## Naming rule

`<subject-slug>-placeholder.jpg` while a placeholder. Real photos may drop the suffix later, but then update the path in the data file in the same change. Keep the manifest table and the data files in sync; `tests/unit/images.test.ts` fails if a referenced file is missing or if a file in these folders is not referenced.

## Not image files (no placeholder needed)

- Logo and favicon: inline SVG and `app/icon.svg`.
- Touch icon: generated by `apple-icon.tsx` (or omitted, see research R9).
- Icons: lucide-react components.
- Background patterns and gradients: CSS only.

## Rendering rules

- Always `next/image` with the `width` and `height` from the data record and a `sizes` attribute:
  - hero: `(min-width: 1024px) 480px, 90vw`
  - clinic: `(min-width: 1024px) 560px, 90vw`
  - department card: `(min-width: 1280px) 280px, (min-width: 1024px) 30vw, (min-width: 640px) 45vw, 92vw`
  - doctor card: `(min-width: 1280px) 280px, (min-width: 640px) 45vw, 92vw`
  - tip card: `(min-width: 1024px) 360px, (min-width: 640px) 45vw, 92vw`
- Only the hero image uses `priority`; all others use the default lazy loading.
- A failed image shows the neutral fallback block (see design-system §7) with the alt text as its caption.
- Image file names and alt text contain no third-party brand names.
